# Data Model: Use Infoblox Fork of CloudQuery

**Feature**: 004-use-fork-repo  
**Date**: 2026-02-22

## Overview

This feature changes configuration values, not data structures. The "data model" here describes which fields in which files change and the rules governing those changes.

## Change Map

### Entity: Plugin Manifest Entry (`plugins.yaml`)

Each plugin entry has an `upstream` block with three fields:

| Field | Before | After | Rule |
|-------|--------|-------|------|
| `upstream.repo` | `https://github.com/cloudquery/cloudquery` | `https://github.com/infobloxopen/cloudquery` | **MUST change** — git clone URL for image builds |
| `upstream.tag` | (unchanged) | (unchanged) | Remains valid — fork has same tags |
| `upstream.commit` | (unchanged) | (unchanged) | Remains valid — fork has same SHAs |

Each plugin entry also has a `build` block:

| Field | Before | After | Rule |
|-------|--------|-------|------|
| `build.plugin_dir` | (unchanged) | (unchanged) | Fork retains directory structure |
| `build.go_version` | (unchanged) | (unchanged) | Fork uses same Go version |
| `build.ldflags_version_path` | `github.com/cloudquery/cloudquery/...` | `github.com/cloudquery/cloudquery/...` (NO CHANGE) | Go module path — NOT a git URL |

### Entity: Dockerfile Build Argument

| Argument | Before | After | Rule |
|----------|--------|-------|------|
| `UPSTREAM_REPO` (default) | `https://github.com/cloudquery/cloudquery` | `https://github.com/infobloxopen/cloudquery` | Default for `git clone`; overridable via `--build-arg` |

### Entity: OCI Image Labels (auto-derived)

These labels are set by `build.sh` from manifest values. They change automatically when manifest values change:

| Label | Before | After |
|-------|--------|-------|
| `io.cloudquery.plugin.upstream-repo` | `https://github.com/cloudquery/cloudquery` | `https://github.com/infobloxopen/cloudquery` |
| `io.cloudquery.plugin.upstream-tag` | (unchanged) | (unchanged) |
| `io.cloudquery.plugin.upstream-commit` | (unchanged) | (unchanged) |

### Entity: Build Index Entry (auto-derived)

The JSON build index (`docs/build-index.md`) is generated by `generate-build-index.sh`. The `upstream_repo` field will automatically reflect the new URL from manifest values.

## Validation Rules

1. **URL format**: `upstream.repo` MUST be a valid HTTPS URL (enforced by JSON Schema: `"format": "uri"`, `"pattern": "^https://"`).
2. **Tag existence**: `upstream.tag` MUST resolve via `git ls-remote` against the URL in `upstream.repo` (enforced by `validate-manifest.sh`).
3. **Commit match**: `upstream.commit` MUST match the SHA that `upstream.tag` resolves to in `upstream.repo` (enforced by `validate-manifest.sh`).
4. **Go module path**: `ldflags_version_path` MUST match the Go package path in the source code's `go.mod` — this is independent of the git URL.

## State Transitions

N/A — this is a one-time configuration migration, not a stateful system.

## Relationships

```
plugins.yaml (upstream.repo)
    │
    ├──► Dockerfile (ARG UPSTREAM_REPO) — passed via --build-arg by build.sh
    │       │
    │       └──► git clone --branch=<tag> <repo> — the actual clone operation
    │
    ├──► validate-manifest.sh — reads repo dynamically for git ls-remote
    │
    ├──► build.sh — reads repo dynamically for --build-arg + OCI labels
    │
    └──► generate-build-index.sh — reads repo for build index JSON
```
