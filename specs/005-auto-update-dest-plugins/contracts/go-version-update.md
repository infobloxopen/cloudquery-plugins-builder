# Contract: Weekly Go Version Update Workflow

**Feature**: 005-auto-update-dest-plugins
**Script**: `scripts/update-go-version.sh`
**Workflow**: `.github/workflows/update-go-version.yaml`

## Purpose

Automatically updates the `go_version` field in all plugin entries in `plugins.yaml` to the latest stable Go release that has been available for at least 2 weeks, ensuring builds stay current with security patches while avoiding day-zero regressions.

## Script Interface

```bash
Usage: ./scripts/update-go-version.sh [OPTIONS]

Options:
  --dry-run     Report the latest eligible Go version without modifying files
  --help        Show usage
```

## Behaviour Contract

### Inputs

- `plugins.yaml` — current manifest
- `https://go.dev/dl/?mode=json` — list of stable Go releases
- `https://api.github.com/repos/golang/go/git/ref/tags/<version>` — release date lookup

### Version Selection Algorithm

1. Fetch all stable releases from `go.dev/dl/?mode=json`
2. For each version (newest first), resolve release date via GitHub API
3. Calculate cutoff: `today - 14 days`
4. Select the newest version where `release_date ≤ cutoff`
5. If no version meets the criterion, no update is performed

### Outputs

| Mode | File Changes | Stdout | Exit Code |
|------|-------------|--------|-----------|
| `--dry-run` | None | Current and eligible Go versions | `0` |
| Default | Updates all `go_version` fields in `plugins.yaml` | Update log | `0` if success, `1` on failure |

### Fields Updated

For every plugin entry in `plugins.yaml`:
- `build.go_version` → new Go version string (e.g., `"1.26.0"`)

All plugins use the same Go version to avoid build matrix complexity.

### Guard Rails

- **Main-only**: The workflow runs only on the `main` branch. If triggered on a feature branch, it exits immediately with no changes.
- **No downgrade**: If the eligible version is older than the current `go_version`, no change is made.
- **Stabilization buffer**: The 2-week minimum age ensures Go releases have time to surface regressions before adoption.

### Error Handling

- Go downloads API unreachable: exit with code `1`
- GitHub API rate limited: use `GITHUB_TOKEN` for authentication (5000 req/hr)
- No eligible version found: exit with code `0`, no changes

## Workflow Contract

```yaml
name: Update Go Version

on:
  schedule:
    - cron: '0 9 * * 1'  # Every Monday at 09:00 UTC
  workflow_dispatch:       # Manual trigger

permissions:
  contents: write
  pull-requests: write
```

### Workflow Steps

1. Generate GitHub App token
2. Checkout `main`
3. Run `update-go-version.sh`
4. If changes detected: `make validate` → create PR
5. PR triggers `pr-validate.yaml` for full CI checks

### PR Format

```text
Title: chore: update Go version to 1.26.0

Body:
## Go Version Update

Updated `go_version` for all plugins: 1.25.6 → 1.26.0

**Release**: go1.26.0 (released 2026-02-08, 14+ days ago)
**Release notes**: https://go.dev/doc/go1.26

---
*Automatically generated by the update-go-version workflow.*
```

## Dependencies

- `curl` — fetch Go downloads API and GitHub API
- `jq` — parse JSON responses
- `yq` (v4+) — update YAML fields
- `date` — date arithmetic
- `sort -V` — version comparison (GNU coreutils)
